## 评分：先解释单位，再解释大小

四个带正则化的在线预测头分别学习接受、拒绝、亲近偏好与主动再选择。输入包括歌曲 / 艺人、召回来源、时间及其他可用情境，以及情境与音乐属性的交互。缺失特征不会冒充已知数值。

每个头的 sigmoid 输出位于 0–1，但未经校准，不宜解读成真实成功率。它们描述不同目标，既不互斥，也不能直接相加得到概率。

```text
S = P + 2.4A − 3R + 2F + 1.5Q − 1.45
```

- `P`：该轮记录的其他排序贡献，例如熟悉度、喜欢和重复控制等。
- `A / R / F / Q`：接受、拒绝、亲近偏好、主动再选择倾向。
- `R` 始终作为负向贡献；相同条件下拒绝倾向增加，分数必然降低。
- `−1.45` 让四个头都为 0.5 时模型合计为零；它不改变候选间的相对次序。
- 系数是当前人工设定的排序优先级，不代表统计校准结果。

旧快照保留当时分数。解释只重表达贡献方向；缺少的历史明细以剩余项呈现，不凭空重建过去的原因。

## 从排序到选择

对一轮 `N` 个候选，当前实现采用：

```text
p(i) = 0.92 × softmax(S / 0.55)[i] + 0.08 / N
```

这个 `p(i)` 是**本轮选择策略的抽样概率**，不是歌曲会被喜欢的概率。决策快照记录候选、分数项与抽样概率；搜索 / 歌单手选没有已知抽样概率，不能套用上一次自动推荐概率。

## 反馈应与动作含义一致

播放证据记录真实输出时长和唯一覆盖，拖动跳过的位置不会虚增听歌时长。自动结束、预览结束、错误结束、手动切换分别处理；单次点按重听不能代替实际重听证据。

「现在不合适」只更新情境相关特征，避免变成对艺人或歌曲的全局厌恶。撤销喜欢向中性更新，并不声称精确撤销所有历史训练。

SQLite 使用后台串行写入和增量保存，保留模型状态、有限决策与播放事件。预取候选和播放地址减少切歌等待，但网络、服务响应及媒体解码仍可能造成延迟。

## BPM：音频证据与覆盖一起保存

实际音频由有上限的下载管道取得，压缩资源上限为 16,000,000 字节。较长歌曲从前、中、后分散抽取最多三个 24 秒窗口；短资源按实际长度调整。各段估计后做一致性与半拍 / 双拍歧义检查。

系统记录片段位置、结果与置信度。预览、未知完整性、片段冲突、下载受限等状态与可信结果区分，不能把某个片段的结果包装成整首歌的已确认 BPM。歌词与标题分析不参与音频节拍测量。

## 照片、意图与位置

云端请求包含当前与近期选择的图片、各自时间、有限场景摘要，以及可选用户自述 / 语义地点。拍摄时间与选择时间分开记录，缺失 EXIF 时不编造拍摄时刻。图片先去除元数据，精确坐标不发送给模型。

意图属于可被纠正的假设，用户自述优先；照片不能确认内在心理状态。云端结果经过结构与可信度检查，不可信字段被舍弃。分析失败不会自动循环付费重试。

新地点存储与距离匹配使用 WGS-84，大陆高德底图显示时才做显式转换；转换仅用于地图展示和选点回读，避免整体偏移或重复转换。
