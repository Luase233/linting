# 霖听 1.4（build 6）

本次对应 [Issue #1](https://github.com/Luase233/linting/issues/1) 中可由源码复核的机制问题。Issue 中的长期体验评估与概率校准仍是后续验证事项；没有把整份研究计划宣称为已完成。

## 已修正的机制

- **选择范围**：从全池 softmax + 额外均匀抽样，改为候选前列主要池及有质量门槛的兴趣探索池；统一预算，移除叠加的新歌奖励。连续早跳会收紧探索。
- **反馈目标**：持续收听使用完整资源的实际 60 秒覆盖目标，自动播放也可提供该结果；「此刻合适 / 不合适」独立学习；喜欢保留长期偏好含义。新目标采用新头，不复用旧接受 / 拒绝软标签权重。
- **召回**：收藏缺失名称分批补全，增加熟悉曲、多个常听艺人、会话邻近和明确意图通道。保留有限通用发现；不把学校、体征机械映射成某类音乐。
- **重复控制**：使用具体歌曲和艺人，不再仅因同属「喜欢歌曲」来源连续扣分。
- **时效与可靠性**：缩短图片场景与推断的有效期，位置质量实际参与模型，可靠移动使旧推断失效；用户明确意图优先。图片已引用地点时不重复加入相同地点特征。
- **解释与审计**：首页先展示依据，人工分数和抽样概率放到可展开诊断中。快照保存可读候选、来源、该曲目标证据数、版本、最终概率与失败重选关联；分别提供图片 / 地点 / 体征移除对照。
- **评估工具**：本地只读脚本输出新标签的时间顺序预测审计、可靠性分箱、Brier / log loss、描述性区间和情境覆盖 / 决策影响；缺失结果保持缺失。

## 数据与升级

使用原 Bundle Identifier 覆盖安装会保留账号、收藏和学习库。旧模型权重及旧决策快照仍可读取；新目标从空权重独立积累。新分数与旧分数不可跨版本直接比较。

照片上传范围、云端供应商及预算不变。诊断自动播放保留审计记录，但不更新偏好、开始次数、重复控制或最近覆盖等学习状态。

## 验证边界

编译、合成音频、目标语义、概率守恒、旧数据兼容、数据库和设备播放检查用于验证实现。它们不能证明推荐已经改善，更不能推出心理状态或因果关系。

真实推荐收益需要继续积累同版本反馈，按完整会话控制条件比较早跳、连续跳过、有效持续收听、明确合适评价和新曲回访。当前不展示适合百分比，不启用未经验证的校准器。配额、评分系数和时效均是可调整的工程参数。
